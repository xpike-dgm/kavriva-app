# T-E3-006c — Browser contract rules

1. objective: Specify the browser boundary before an E2 browser or generic client is allowed to use E3 product APIs.
2. outcome-link: FL3.1.4/F3.1.4, ADR-006 Decision 9 — storage, origin, CSRF/PKCE, step-up and lookup disclosure limits are explicit.
3. preconditions + completed dependencies: The planning index has no hard dependency. PR #8 merged the repository DB/RPC inventory, while hosted inspection remains pending. T-E3-006b is separate and can remain pending without blocking this contract.
4. mandatory reads: planning 00_CONTROL/AI_START_HERE.md, `planning 07_AI_ARCHITECTURE/TASK_EXECUTION_PROTOCOL.md`, `planning 07_AI_ARCHITECTURE/MODULE_BOUNDARIES.md`, `planning 06_DELIVERY_PLANNING/TASK_INDEX.md`, ADR-002/004/006/010, DEC-0068/0069; E2 and E3 manifests, current E3 API, T-E3-006a inventory, current Supabase Auth/Storage guidance.
5. allowed paths: `[[vault/PROFILES/authorization-tuple-browser.md]]`, E2/E3 manifests, this pack, `[[vault/REGISTRY/T-E3-006c.md]]`, `[[vault/EVIDENCE/E-DEV-007.md]]`, generated registry and routing indexes.
6. forbidden areas: Hosted Supabase, credentials, buckets, schema migrations, browser framework selection, privileged production activation, E3/E5 runtime authorization code, and T-E3-006b or T-E3-007 acceptance claims.
7. expected artifact changes: A framework-independent, implementable browser profile of the existing authorization tuple with explicit negative examples and links to the existing E3/E2 seam; no new catalog contract.
8. acceptance + negative cases: Cover browser/private-object storage, exact origin/CORS and cookie CSRF behavior, PKCE callback binding, transaction-bound step-up, and tenant-safe operation lookup. State how stale/unknown cases fail closed and how lost responses reconcile. Reject any browser-state, console, signed-URL or provider-role substitute for current product authority.
9. validation / architecture / integration checks to run: E10 `run_all.py`, generated-index reproducibility, Git diff checks, PR CI and independent task-level review. No browser runtime exists, so no browser implementation test is claimed.
10. migration / rollback needs: Documentation and manifest references only; reverting this PR restores the previous text and index entries. No hosted effect.
11. responsive / accessibility rules: No screen change. Future E2 implementation must preserve ADR-010 keyboard, screen-reader and bounded-data requirements; this contract cannot claim those tests passed.
12. evidence + handoff format: `[[vault/EVIDENCE/E-DEV-007.md]]` records the contract digest, checks, review and explicit implementation/hosted limits.
13. graph-update records: Create `[[vault/REGISTRY/T-E3-006c.md]]`, regenerate registry/routing indexes, and leave T-E3-006b and T-E3-007 unclaimed.
14. escalation rules: If the future browser shape cannot satisfy session, CSRF or private-object rules, keep its privileged capability HELD and seek an explicit owner decision before changing the contract.
